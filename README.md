# xynovim

**A Neovim config for Rust that goes after RustRover: instant diagnostics, a real debugger and test UI, a git safety net, and a test suite you can run yourself.**

Built on [LazyVim](https://github.com/LazyVim/LazyVim), for Linux (Arch is what it is developed on), with the **Island Dark** colour scheme converted from a RustRover export. Everything on this page was recorded from the real config running on the small demo crate in [`demo/netwatch`](demo/netwatch): the screenshots and videos are regenerated by one script ([`docs/media/record.sh`](docs/media/record.sh)), nothing is mocked up.

> The previous from-scratch Windows config lives on the [`windows-legacy`](../../tree/windows-legacy) branch. Every notable change is in [CHANGELOG.md](CHANGELOG.md).

## What you get

- **Two diagnostic tiers**: rust-analyzer answers while you type, clippy follows about half a second later, on every keystroke and before any save.
- **A debugger and a test runner that look like the ones in an IDE**: breakpoints with Rust-aware variable views, a test summary tree, coverage in the gutter.
- **A safety net**: every save is snapshotted as a git ref (a "Local History"), and the AI agent runs inside a sandbox.
- **Treesitter everywhere**: sticky scope, text objects, SQL injected into `sqlx` strings, a live syntax-tree view.
- **Tested**: 1069 passing checks across 24 spec files, one per feature area, runnable with one command after a clone ([below](#tests-run-them-yourself)).

## Tour

### Two-tier diagnostics

rust-analyzer's own diagnostics appear as you type (type errors in about 0.01 to 0.15 s). [bacon-ls](https://github.com/crisidev/bacon-ls) runs clippy against a hardlinked shadow of your workspace on every buffer change (about 0.56 s median), so lints show up before you save. Each message shows its first line plus the source; the full text is one `<leader>cd` away.

### Git, and a safety net

lazygit (with `delta`), diffview for diffs, merge conflicts and file history, `mergiraf` as a syntax-aware merge driver, and **Local History**: every save (manual or auto-save, throttled) also writes the whole worktree, untracked files included, as a commit under `refs/lochist/` using a private index. Deleted files and `git reset --hard` become recoverable without touching your real index, stash or branches. `:LocalHistory` browses and diffs, `:LocalHistoryRestore` restores, `:LocalHistoryPrune` cleans up.

### The AI agent, sandboxed

[99](https://github.com/ThePrimeagen/99) with the Claude Code provider is wired in (`<leader>9`), and its `claude --dangerously-skip-permissions` runs inside **bubblewrap**: the filesystem is read-only except the project and Claude's own state, credentials and agent sockets are hidden, `.git/hooks`, `.git/config` and Claude's settings are locked read-only, the environment is scrubbed of tokens, and every request is preceded by a Local History snapshot with auto-save paused. It is a seatbelt, not a jail: the network stays open (details in [docs/DETAILS.md](docs/DETAILS.md)). There are no screenshots: the sandbox has no UI, and a real request needs an account.

## Install

Prerequisites (`scripts/bootstrap.sh` checks the ones it needs itself (see the script) and prints what is missing; `:checkhealth xynovim` checks the rest later, with what each one is for):

- Required to bring the config up: `nvim` 0.12, `git`, `curl`, `tar`, `unzip`, `gcc` (tree-sitter parsers), the `tree-sitter` CLI (nvim-treesitter builds parsers with it; Mason installs it as the tree-sitter-cli package, `:checkhealth xynovim` warns when it is missing), `gzip`, `node` and `npm` (Mason's `markdownlint-cli2`, `markdown-toc`, `yaml-language-server`).
- Required for the Rust workflow: `cargo`, `rustup` (with the `stable` toolchain, its `clippy` and `llvm-tools` components) and `rust-analyzer` on PATH (`rustup component add rust-analyzer`).
- Installed by Mason (`scripts/bootstrap.sh` step 3 runs `scripts/provision.lua`, which also downloads the treesitter parsers; otherwise they come with the first interactive start): `bacon-ls` >= 0.31.0, `codelldb`, `taplo`, `wgsl-analyzer`, `marksman`, `lua-language-server`, `json-lsp`, `yaml-language-server`, `tree-sitter-cli`, `markdownlint-cli2`, `markdown-toc`, `stylua`, `shfmt`. The `bacon` package is a separate Mason package (also pulled in with `bacon-ls`); its binary is **not** used: bacon-ls runs cargo/clippy directly. `bootstrap.sh` stops without `cargo`, `rustup` or `rust-analyzer`; `BOOTSTRAP_SKIP_PREREQS=1` goes on anyway (a machine without Rust).
- Optional, each one only costs its feature: `mold` + `clang` (linker, see below), `cargo-nextest`, `cargo-deny`, `cargo-expand`, `lazygit`, `delta`, `bwrap` (the 99 sandbox).

```sh
git clone https://github.com/xynorash/xynovim ~/.config/nvim   # or ln -s <checkout> ~/.config/nvim
~/.config/nvim/scripts/bootstrap.sh
```

Why a script and not just `nvim --headless '+Lazy! restore' +qa`: on an empty plugin directory lazy.nvim installs in several rounds (a plugin's own specs, such as LazyVim's extras, are only read once it is cloned) and rewrites `lazy-lock.json` after every round with the plugins it knows so far. The pins of the ones found later are dropped, so those land on their newest commit (5 of 79 did in the first fresh-install tests, before 18 theme-only plugins were dropped (61 plugins are locked now), and the lockfile changed; kulala was a sixth until `submodules = false` fixed its pin, see step 10). The script runs `Lazy! install`, puts the original lockfile back, runs `Lazy! restore` and fails if `lazy-lock.json` differs afterwards; CI runs it and then `git diff --exit-code lazy-lock.json`. A plain `Lazy! restore` on an install that already holds every plugin ended with an identical lockfile in the same test.

## Keys you will use

`<leader>` is Space; which-key shows the menu of every prefix.

| Keys | What |
| --- | --- |
| `<leader>r…` | rust-analyzer: `rv` extract variable, `rf` function, `rc` constant, `ri` inline, `rs` structural search / replace, `rj` join lines, `rm` expand macro, `rh` / `rH` HIR / MIR, `re` explain error code, `rl` usages in file (read / write), `ru` go to super method, `rw` / `rW` workspace symbol (+ dependencies), `rF` features / target, `rX` targets, `rZ` cargo tools, `rN` HTTP routes, `rR` reload workspace; `<A-j>` / `<A-k>` move item |
| `<leader>d…` | debugger: `db` breakpoint, `dc` continue, `dr` / `dR` debuggables (file / workspace), `du` dap-ui |
| `<leader>t…` | tests: `tt` file, `tr` nearest, `tT` all, `ts` summary, `to` output, `tw` watch, `tD` doc-tests, `tc` run coverage, `tg` toggle coverage signs |
| `<leader>g…` | git: `gg` lazygit, `gv` diffview, `gV` branch vs origin, `gF` file history, `gH` local history |
| `<leader>c…` | `cd` diagnostic float, `cj` split / join (treesj), `cI` / `cO` incoming / outgoing call trees, `cn` doc comment stub |
| `<leader>9…` | the 99 agent: `9v` vibe, `9s` search, `9o` last interaction, `9x` stop |
| `<leader>H`, `<C-e>`, `<M-1..4>` | harpoon: add file, menu, jump |
| `<leader>uO`, `uB`, `uu` | toggle editor transparency, colour-blind diagnostics, undotree |

## Commands

`:RustContext` (features and target for both tiers), `:RustTargets`, `:RustTools`, `:RustNew`, `:RustRoutes` (axum / actix / rocket routes), `:RustRestart`, `:ActJob` (run the GitHub Actions job under the cursor with `act`), `:LocalHistory`, `:LocalHistoryRestore`, `:LocalHistoryPrune`, `:ColorblindDiagnostics`, `:checkhealth xynovim`. Plugin management is stock LazyVim: `:Lazy sync` updates (the update checker is off), `:LazyExtras` toggles extras, `:Mason` manages language servers.

## Tests: run them yourself

The config ships with an automated suite: **24 spec files, 1069 checks passing, 23 skipped with a stated reason, 0 failing**, in about six minutes. Each file runs in its own headless Neovim with the full config and a hard timeout, so a hanging test cannot stall the rest. After cloning and bootstrapping:

```sh
scripts/test.sh                  # everything (or: make test)
scripts/test.sh routes smoke     # only spec files whose path contains one of the words
scripts/test.sh --list           # the spec files, nothing run
scripts/test.sh --coverage       # also a per-file line-coverage report
```

![the test runner finishing four spec files: 129 passed, 0 failed](docs/media/10-test-suite.png)

Video: [10-test-suite.mp4](docs/media/10-test-suite.mp4)

- **Nothing of yours is touched**: the specs run against a temp config / state / cache; only the installed plugins are reused. Missing tools (rust-analyzer, tmux, bubblewrap, lazygit, ...) make their specs **skip with a message**, never fail.
- **One spec per feature area**: startup and options, the Island theme, every `<leader>r` command, `:RustContext`, `:RustTargets`, Local History, auto-save guards, the agent sandbox and the 99 guard, the two diagnostic tiers' configuration, server supervision, debugger and test integration, git and lint tooling, snippets and treesitter injections, the UI helpers, health / bootstrap / CI, and the claims this documentation makes. [tests/COVERAGE.md](tests/COVERAGE.md) maps every feature to the spec that tests it and lists what has no test and why.
- **Line coverage** of the repo's own Lua is about 86 % (`--coverage`; the denominator is estimated, treat it as a guide).
- **CI**: the [ci workflow](.github/workflows/ci.yml) runs `scripts/bootstrap.sh` (clone plugins on their locked commits, download parsers and Mason tools), a startup smoke test, then `scripts/test.sh`, on a clean Ubuntu machine for every push.
- How the harness works, how to write a spec and what the helpers offer: [docs/TESTING.md](docs/TESTING.md).

## The demo project and the recordings

[`demo/netwatch`](demo/netwatch) is a small, realistic Rust crate (a trait, a CLI, unit and integration tests, features) used as the target of every screenshot and video above and handy for trying the config. The recordings are plain [vhs](https://github.com/charmbracelet/vhs) tapes in [`docs/media/tapes/`](docs/media/tapes); `docs/media/record.sh` copies the crate to a temp dir, warms the build and replays them in a real terminal, so they can be regenerated after any change:

```sh
docs/media/record.sh            # everything
docs/media/record.sh 05-tests   # one tape
```

(needs `vhs`, `ttyd`, `chromium`, `ffmpeg` and the JetBrainsMono Nerd Font).
