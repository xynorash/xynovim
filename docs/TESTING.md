# Testing

The suite, how it runs and how to write a spec. The overview with the numbers is in the [README](../README.md#tests-run-them-yourself).

## Tests

```sh
scripts/test.sh                 # or: make test
scripts/test.sh routes smoke    # only spec files whose path contains one of the words
scripts/test.sh --list          # the spec files, nothing run
scripts/test.sh --coverage      # also a per-file line-coverage report (make coverage)
scripts/test.sh --timeout 300 -v
```

- **What runs**: every `tests/*_spec.lua`, each in its **own** `nvim --headless` process with the full config and a hard `timeout` (default 120 s, `--timeout N` or `$TEST_TIMEOUT`; a hanging file is killed and counted as failed, the suite goes on). Per file it prints PASS/FAIL/TIMEOUT/CRASH with passed/failed/skipped counts, failures (with a trimmed traceback) and every skip with its reason, then a total. Exit status: 0 = no failure (skips allowed), 1 = a failure, timeout or crash, 2 = nothing matched or the setup is missing.
- **Isolation**: the config is this checkout through a temp `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_CACHE_HOME` and `TMPDIR` are temp dirs removed at the end (shada, undo, `lsp.log`, local history of the specs never touch yours), `XDG_DATA_HOME` is the **real** one: the installed plugins are reused, nothing is installed. A CI job or a fresh machine must run `scripts/bootstrap.sh` first (the script says so and exits 2 when no plugins are there). The script warns if `lazy-lock.json` changed during the run.
- **Cleanup**: temp crates and dirs, language servers, spawned jobs and tmux servers (private sockets named `xynotest-<pid>-*`) are removed by the spec helpers at the end of each file and again by the script (each nvim runs in its own process group that is signalled afterwards).
- **Writing a spec**: `tests/<name>_spec.lua` with `describe` / `it` / `before_each` / `after_each` / `pending` / `skip(reason)` (a small framework in `tests/harness.lua`; plenary's busted was not used because `PlenaryBustedFile` starts a nested nvim with its own minimal init, which would not load this config, and cannot carry the timeout or the coverage hook). `local H = require("xynotest.helpers")` (a private name: `tests.helpers` collides with other plugins' `lua/tests/`) gives assertions (`eq ok not_ok is_nil match no_match has throws`), `wait_for(pred, ms, msg)`, `wait_lsp(name, bufnr)`, `feed(keys)`, `open(path)` (also fires `User VeryLazy`, which never fires headless), `clients()`, `diagnostics(source)`, `messages()`, `capture_notify()`, `fixture(name, {git=true})` / `open_fixture(name, rel)` (a private copy of a fixture in a temp dir), `git(dir, ...)`, `sandbox_sh(script, project)` (a bash script inside the 99 sandbox wrapper), `tmux(args)`, `spawn(cmd)`, `tmpdir()`, `cleanup()`. `H.need_rust()`, `H.need_sandbox()`, `H.need_tmux()` (in a test or `before_each`) and `H.skip_file(reason)` skip with an explicit message when the tool is missing or unusable; `XYNO_TEST_SKIP_RUST=1` forces the Rust ones to skip.
- **Fixtures** (`tests/fixtures/`, committed, copied per test): `basic` (lib + bin + integration test + trait + one clippy finding), `workspace` (two members, a path dependency, features `ssr`/`csr` with a `compile_error!` when both are on), `broken` (type error), `no-deps-lab` (a crate without dependencies and an unresolved `Uuid`), `standalone.rs` (no Cargo.toml), `sql_and_routes.rs` (sqlx strings and axum/actix routes).
- **Specs now** (33 files, 1519 tests: 1496 pass and 23 are skipped with a reason, 0 fail; about 12 minutes on this machine (the six minutes of the 24-file suite doubled with the new Rust and network specs), the slowest file is `keymaps-global` at 40-80 s): one spec per feature area, `tests/COVERAGE.md` maps every feature to its spec and lists what has no test and why. `smoke_spec.lua`, `harness_spec.lua`, `routes_spec.lua`, `rust_spec.lua` (the original four, the others are named `<area>_spec.lua`): `startup-and-options`, `theme-island`, `keymaps-global`, `keymaps-rust`, `rust-context`, `rust-routes`, `rust-tasks-tools`, `rust-analyzer-config`, `bacon-ls-config`, `server-supervision-statusline`, `dap-neotest-coverage`, `auto-save-disk-guard`, `agent-99-guard`, `agent-sandbox`, `local-history`, `git-lint-supply-chain`, `snippets-completion-injections`, `ux-menu-diagnostics-colourblind`, `health-bootstrap-ci`, `test-infra-readme-claims`; the macros and dependencies work added `crate-meta`, `deps-freshness`, `crate-add`, `crate-features`, `import-engine`, `crate-import`, `macro-attrs`, `macro-tools` and `macros-deps-flows` (the last runs four cross-module flows on temp copies of the fixtures with real cargo, crates.io and rust-analyzer; the network parts skip with a message offline). The 23 skips are `pending` entries (a real claude request, interactive pickers, the network install, ...) and known bugs written as assertions of the correct behaviour (they start passing when the bug is fixed). A spec that needs more than the default timeout says so in a `-- xyno-timeout: N` line in its first 15 lines (`keymaps-global`: 400).
- **Coverage** (`--coverage`): `tests/coverage_hook.lua` (a `debug.sethook` line collector, stdlib only, loaded with `--cmd` so it sees the config's own startup, coroutines included) records the executed lines of `lua/`, `colors/`, `plugin/` and `after/` per spec file; `scripts/coverage.lua` (run with `nvim -l`) merges the dumps and prints per-file percentages. The executable-line denominator is **estimated from the source text** (blank, comment and closer-only lines excluded), so read the numbers as a guide, not an exact figure. A covered run is several times slower (the hook switches LuaJIT's compiler off) and code in a child nvim process is not seen. Last run (before the macros and dependencies modules, not re-run since): **86.4 %** (3626 of an estimated 4199 lines; the per-file figures are printed by the run: `island/init.lua` 99 %, `rust_context` 95 %, `lsp_status` 92 %, `local_history` 84 %, `agent_sandbox` 79 %, `dap.lua` 72 %, `lazy.lua` 42 %, `transparency.lua` 35 %, the one-line plugin specs 35-60 %). Under `--coverage` 9 more tests skip (the 8 rust-analyzer ones of `keymaps-global` hang with the line hook, the colourscheme picker one takes 20+ minutes), so the covered run is 968 passed, 43 skipped; coverage of code that runs in a child nvim is not seen.
- **CI**: the `ci` workflow runs `scripts/bootstrap.sh`, then `scripts/test.sh`, then the lockfile check again. rust-analyzer is installed there, so the Rust specs run; where a tool is missing its specs skip.
