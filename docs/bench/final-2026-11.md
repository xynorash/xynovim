## Limits (not measured, or only partly)

- Linux only (reads `/proc`); one machine, one run of this script; load average at start is above.
- Startup is measured in a tmux pty: it includes exec and the terminal protocol handshake of nvim, but not the terminal emulator's own time to first paint.
- The demo crate has two source files. Memory, indexing time and clippy time on a large workspace are not covered.
- A diagnostic cell reads `none` when no matching diagnostic arrived within 20 s; it does not say the config could not be set up to produce one.
- Large-file numbers are for a file outside a Cargo crate, generated by the harness.

## Comparison with the baseline (`baseline.json`, git 84b0277, 2026-11-11)

Same machine, same harness, same demo crate, pinned plugins (`lazy-lock.json`, no `XYNOVIM_DEV_PLUGINS`). Single runs of the whole harness, medians of 10 starts where the harness takes them; run-to-run noise on this machine is a few ms on startup (the "max" values show it) and a few percent on the latency cells. "Regression" below means worse than that noise.

The 100 003-line row looked like a small regression in the first comparison, so I measured it again: six more runs of this checkout gave open 53.6, 58.2, 55.6, 59.2, 55.4 and 55.9 ms and a stall of 23.5 to 30.0 ms; three alternating runs of the baseline commit (`git archive 84b0277`, `BENCH_CONFIG`) on the same machine state gave open 54.5, 60.2 and 54.3 ms and a stall of 26.7 to 32.2 ms. The baseline code now measures the same as the final code, so the difference between the two recorded files is the machine state of the day, not a change in the config. In this mode (snacks.nvim's bigfile, no LSP, no treesitter) `largefile.lua` does nothing but set a flag.

What this run found and fixed on the way: an uncommitted change from an earlier session (a bisection in `island.lift`, and `lazy = true` on `nvim-dap-virtual-text`, which had made nvim-dap, mason-nvim-dap and mason load at every start) used `//`, which LuaJIT does not have, so the colourscheme failed to load and 88 checks failed; fixed in 85db1a3. A bench run before that fix, and one that measured `~/.config/nvim` instead of this checkout (the harness uses `XDG_CONFIG_HOME` as given when it is set; run it with `env -u XDG_CONFIG_HOME` unless you mean it), are not used here.

Not measured: a large workspace, indexing time of a big crate, the dev-plugin branches (`XYNOVIM_DEV_PLUGINS`; the +1.3 to +2.8 ms of the Rust IDE features are in [ide-features-2026-11.md](ide-features-2026-11.md)), other editors (`scripts/bench/compare.sh` is for the owner).
