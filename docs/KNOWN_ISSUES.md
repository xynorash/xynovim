# Known limitations

Things that were found, decided and left alone (upstream behaviour, by design, or not worth the risk). Each is verified by hand; none loses data. If one bites you, open an issue.

- **Documented, not fixed** (upstream, by design, or not worth the risk): the multi-location breakpoint on a `format!` line (lldb resolves 3 locations, `continue` stops 3 times; there are no F-key maps); an LSP multi-file rename is undone per buffer (`u` in one file leaves the others renamed; auto-save then writes the half state); moving a module file out of the module tree with `<leader>cR` leaves the `mod` declaration (rust-analyzer); `<leader>rR`, `rP`, `<A-j>`, `<A-k>` give no feedback; the inc-rename preview omits occurrences inside macro arguments (the commit changes them); `gr` waits 300 ms because nvim 0.12's `grr`/`gra`/`grn`/`gri`/`grt`/`grx` make it a prefix; `<leader>dr` before rust-analyzer is ready does nothing; a panic stops in `__rustc::rust_panic` with the workspace frame six up; a compile error during a neotest run keeps the old results (see `<leader>to`); flamegraph leaves `flamegraph.svg` and `perf.data` in the project root; an edit inside a submodule is not in the parent's local history (only the gitlink; the submodule's own repo gets it on its `refs/lochist`); the persisted `:RustContext` choice has no statusline indicator; crates.nvim reports "upgrade available" twice and taplo hovers next to crates.nvim in `Cargo.toml`; mini.pairs after an escaped quote leaves a stray `"`; the coverage summary float may have a doubled border; toggle notifications show `**bold**` asterisks; `99.log` is truncated per nvim session (upstream); any other lint that the two tiers word and code differently still shows twice (only `unsafe_op_in_unsafe_fn` / `E0133` is mapped); a line with many diagnostics shows a run of bullets without a count; the persisted `:RustContext` choice has no indicator; `~/.claude/jobs`, `state`, `backups` and `daemon.*` stay writable inside the 99 sandbox (making them read-only was not tried against a real claude); `treesj` has no `match_block`, plain-string `Regex::new("...")` gets no regex injection, doc comments get no markdown injection; wgsl-analyzer's "Project discovery failed" error message on every `.wgsl` open; the codelldb REPL is in commands mode (`?expr` evaluates, `sum + 100` does not); kulala's first scripted request waits for its `npm install` and rollup build (about 70 s, needs network); a standalone `.rs` opened after a crate file gets no diagnostics; an unwritable `XDG_CACHE_HOME` or `XDG_STATE_HOME` gives an init.lua / lazy.nvim E739; `<leader>rm` on built-in derives says "No macro under cursor!" (use `cargo expand`).

- Not fixed (low, as in the field test list): spell noise on Rust words, `rl` kind labels, snippets mid-expression, kulala `Rq`, bigfile undo files, `.http` conceal, XDG dirs unwritable, picker `target/` without `.gitignore`, dashboard title, the README items of the field test's docs-only list that round 1 already changed.

- Not fixed, decided: the neotest "no test at cursor" notice (neotest's own `run` prints "No tests found", not reproduced), `rm` only on the macro name, `rh` on a fn name, `cc` on a doctest body, extract assists without a rename prompt, treesj and `gc` quirks, a first-line Trouble formatter, the right-click submenu in the TUI (not reproduced, no flat menu), a DAP attach configuration, `positionEncodings` warning in `:checkhealth vim.lsp` (rust-analyzer utf-8, bacon-ls utf-16; harmless), `bootstrap.sh` exiting before Mason's async downloads finish (Mason resumes on the next start), `:RenameUndo`, the kulala `Rq` float (upstream).

- **Known and not fixed** (decided): two nvims on the same workspace share bacon-ls's single `target/bacon-ls-live/shadow`, so one's unsaved text can show up as clippy errors in the other (upstream; open one nvim per workspace); a multi-file rename is undone per buffer (`u` in one file leaves the others renamed: use `<leader>gH` local history to revert it); typing hitches in a 1 MB / 50k-line Rust file (cause not found); clippy waits while another cargo holds `~/.cargo`'s package-cache lock; a stored `:RustContext` feature that no longer exists makes clippy fail (`:RustContext reset`); `:RustRestart` leaves clippy blind to unsaved text until the next edit; after editing a proc-macro crate use `:RustRestart` (`reloadWorkspace` does not clear "proc-macro map is missing"); neotest shows `#[ignore]` tests and doctests as passed after an all-green file run (use `<leader>tD`); `<CR>` accepts blink's preselected fuzzy match; the statusline drops the file name at 80 columns; Trouble and raw LSP messages of bacon-ls items keep the full multi-line rustc text; run `:Lazy clean` once on an existing install for the 18 dropped theme plugins.

- **Field test of the macros and dependencies phase, not fixed (not caused by the phase, see the report)**: a slow `<Space>r<key>` in a non-Rust buffer (the hidden `<leader>r` stubs give which-key nothing to hold, `r` is replaced after `timeoutlen`); `<CR>` in a comment or string accepting blink's preselect and `snippets_allowed` reading a stale tree; the 99 sandbox (`/proc/1/environ` shows scrubbed variables, the HIDDEN list is a denylist, no warning without bwrap, `target/` and project files stay writable); Local History with a corrupt private index, long branch names, `info/exclude`; `:RustNew` in a directory with `#` or `%`; neotest ignored tests and doctests staying "running"; cross-tier duplicates, float source, clippy prefix; one-level call trees; bacon-ls with a space in the project path; "clippy ok" for a non-member crate; a pinned toolchain without rust-analyzer (generic restart notice); cross-directory `<leader>cR`; SSR inside macro arguments; Overseer cargo templates ignoring `:RustContext`; `:RustRoutes` without `scope` / `nest` prefixes. A dependency glob (`use serde::*`) silences the unknown-crate hint for the whole file, and buffers above 20000 lines get no unknown-crate hint and no syntax-scan auto-import (use the `:ImportName` / code action path).
