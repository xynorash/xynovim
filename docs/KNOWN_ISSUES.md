# Known limitations

## Fixed since the last version of this list

Each has a regression spec in `tests/known-issues_spec.lua` (the live debugger one in `tests/dap-neotest-coverage_spec.lua`).

- **A multi-file LSP edit (rename, code action) is undone as a whole.** Neovim has one undo tree per buffer, so `u` after a project-wide rename used to undo one file and leave the others renamed, and auto-save then wrote that half state. `lua/config/rename_undo.lua` remembers each buffer's undo state before and after an `apply_workspace_edit` that changes text in two or more buffers; `u` (and `<C-r>`) in one of them, while it still sits exactly at the state the edit left, goes back (forward) in all of them. A count, a buffer that was edited since, a single-file edit, or an edit that also creates/renames/deletes files (a module rename) get the stock `u`. If another file was edited since, it is left as it is and the message says so. Limit: `:undo N`, `g-` and the undotree plugin are not grouped.
- **A panic stop selects your frame.** The stop is still in `rust_panic` (that is what makes the locals of the panicking function readable), but the frame nvim-dap jumped to was the Rust runtime's (`__rustc::rust_panic`, std source usually not on disk) with the workspace frame five or six up. `lua/config/dap_panic.lua` selects the first frame that is not runtime after such a stop and says so; the full stack is still there (`dap.down()`). Checked live with codelldb 1.12.3 on a panicking binary (see the spec); the frame choice goes through nvim-dap's `Session:_frame_set`, a private function, guarded with `pcall`.
- **crates.nvim's diagnostics are published once.** Every diagnostic of a crate was set twice per update (two bullets, two Trouble entries). `lua/plugins/crates.lua` drops exact repeats on their way to `vim.diagnostic.set` in crates.nvim's two namespaces. Live probe with `serde = "0.9"`, `log = "0.3"`: 4 crates diagnostics before, 2 after. The cause is crates.nvim's, not fixed upstream.
- **A quote after a backslash leaves no stray `"`.** mini.pairs' `closeopen` jumped over the auto-inserted closing quote even after a backslash, so `"a\"b"` ended up as `"a\"b""` in text and Lua buffers (Rust mostly hid it through the string capture). `lua/plugins/mini-pairs.lua` inserts the quote itself after an odd number of backslashes.
- **Naming lints show once** (see the lint line below).

Things that were found, decided and left alone (upstream behaviour, by design, or not worth the risk). Each is verified by hand; none loses data. If one bites you, open an issue.

- **Other 99 providers are not sandboxed**: `<leader>9P` can switch to OpenCode, Cursor, Gemini or Kiro only under an explicit opt-in (`vim.g.xynovim_99_sandbox = false`, or `vim.g.xynovim_99_allow_unsandboxed = true` when no sandbox backend exists). They run with no sandbox, no snapshot and no auto-save pause on any OS; the opt-in is re-checked on every request (revoked: the request is refused) and each request warns. Only the Claude Code provider is guarded.
